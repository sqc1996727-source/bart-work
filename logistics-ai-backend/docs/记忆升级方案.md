# 巨龙记忆升级方案（对标 Grok Bot，社区验证做法）

> 日期：2026-11-23。方向已由老大拍板：**不接外部框架（Mem0/Letta 等），抄社区验证的正确做法，在巨龙现有记忆模块上升级。**

---

## 一、现状诊断（已扒代码确认）

巨龙现在有**三套记忆并存，各管各的，没有一套会「自己长」**：

| 表 | 层 | 入口 | 检索 | 特点 |
|---|---|---|---|---|
| `workplace_memory` | 工具层 | `save_workplace_memory`/`search_workplace_memory` | rapidfuzz 模糊匹配 | 带版本、有效期、岗位隔离、留痕，但只能人手动 save |
| `memories` | AI 服务层 | `save_memory`/`retrieve_memories` | 纯词重叠打分 | 注进 SYSTEM_TEMPLATE，检索弱 |
| `long_term_memories` | 最早遗留 | （无直接工具） | （在 workplace_memory.search 里兜底查） | 最老一套，跟上面俩不通 |

**病根**：三套记忆、三个入口、三条检索，谁也没串起来，更没一套会「自己长」。模型读哪个、存哪个，全看走哪条路径。

**记忆「没跑起来」的本质**：唯一能让记忆增长的入口是「人手动调 save 工具」。没人调，就永远空着。没有「从每次对话/干活里自动沉淀」的机制。

---

## 二、要抄的三条社区正确做法（来自 Mem0/Graphiti/Letta/PowerContext + PokeClaw 设计文档）

1. **记忆留在巨龙自己的 SQLite 里，不接云、不接外部向量库。** 这些框架自己都在往「本地 SQLite」收敛（PowerContext 明说「SQLite 是最简单的首选」）。巨龙本来就在对的一侧。

2. **「抽取即决策」——不让模型额外调一次 LLM 判断「要不要记」。** 让模型在它**本来就要跑的工具循环里**，顺手决定「要不要存、存什么」。零额外 LLM 调用、零额外延迟。这是 Mem0 和 PokeClaw 文档共同验证的关键做法。

3. **每条记忆带「时间维度」，不是简单覆盖写。** 抄 Graphiti/Zep 最值钱那半条：事实带有效期区间，能回答「这件事在什么时候是真的」。巨龙 `valid_from/valid_until` 已有雏形，补成真的时间维度，且**区分「事实何时为真」和「系统何时知道」**。

**明确不抄的**：Mem0 的知识图谱（锁 $249/月 Pro）、Letta 的独立 runtime（等于换掉巨龙整个 agent）、向量库检索（巨龙记忆量小，暴力/词法足够，引入 embedding 反而破「数据不出门」的定位）。

## 三、升级方案：三套收敛成一 + 让它自己长

### 第 0 步：收敛（先收拾乱局）
把三套记忆统一到一个「真源」，避免「模型存的、工具查的、老表留的」三处割裂。**以 `workplace_memory` 表为唯一真源**（它最全：版本/有效期/隔离/留痕），把 `memories` 和 `long_term_memories` 的职责合并进来，其余两表降级为「历史兼容，不再新写」。

### 第 1 步：让记忆「自己长」（核心，对标 Grok 的 memory 自己长）
加一个**自动沉淀环节**，两个触发点：

1. **用户纠正它** → 后台把「纠正的话」提炼成一条记忆，存它名下，下次不再犯；
2. **它干完一件活** → 后台把「这次结果 + 结论」提炼成记忆，下次能接上、能对比。

**关键机制（抄「抽取即决策」）**：不额外调一次 LLM 判断「要不要记」。而是——模型在工具循环里，**本来就有一个 `save_workplace_memory` 工具**。把「要不要调它、存什么」交给模型在现有工具循环里顺手决定。**零新增 LLM 调用。**

同时给它一个**兜底**：对话结束后，把「用户这轮是否有明确纠正/偏好表达」做一个轻量的确定性检测（关键词/句式），命中了才把原文交给模型提炼，不命中就不动。**这样既不额外烧 token，又不会漏掉「老板说记住」这种明确信号。**

### 第 2 步：时间维度（抄 Graphiti 半条）
`workplace_memory` 已有 `valid_from/valid_until`，补两点：
- 检索时**严格按「当前时间在有效期内」过滤**，过期的不进候选；
- 记录**「录入时间」与「事实生效时间」分开**（已有 `created_at` vs `valid_from`，够用，主要是把检索口径统一到「valid_from <= today < valid_until」）。

### 第 3 步：检索升级（轻量，不引入向量库）
现有 rapidfuzz 模糊匹配对中文够用，补一条「**主题分组 + 版本取最新 + 冲突显式暴露**」——这是巨龙已有、别家付费才有的差异点，保留并跑起来。

## 四、验收标准

1. **自动沉淀**：老板纠正一句「这家叫张三不叫张老板」，下一轮问「张三」时，模型能带回这条记忆（不再叫错）。
2. **不额外烧 token**：沉淀不触发「额外一次判断要不要记」的 LLM 调用，只在已有工具循环里顺手做。
3. **不破坏隔离**：个人记忆/企业记忆、老板/员工岗位隔离，回归全过。
4. **留痕**：每次自动沉淀都写 audit。

---

## 五、待老大拍板的一个点

自动沉淀的**触发方式**，两个做法（之前问过，方向定为「先稳后自动」）：

- **A（稳）**：用户明确说「记住：XXX」或点一下「记住这条」才记。不漏不误记，但要多一个动作。
- **B（自动）**：模型在工具循环里自己判断要不要记。全自动，可能误记。

**倾向：先做 A 的「兜底确定性检测」 + 让模型在工具循环里可顺手调 save（B 的一半），先保证「明确要记的绝不漏、明确不要记的绝不误记」，跑稳后再放开全自动。**
