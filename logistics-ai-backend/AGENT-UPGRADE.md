# Agent 能力强化（产品化分支）

保持同一共享前端、现有业务 API、角色隔离、真实财务确认及独立企业数据库。本轮不修改主分支，不部署，不调用真实模型或客户业务。

## 已实现代码
- V3 实际服务接入深度执行策略；默认 48 工具轮、80 模型请求、1200 秒、25 万已报告 token。参数由部署端配置，不对简单请求强制规划。
- 模型临时网络/服务错误有限退避重试；参数错误或不可用工具可由模型修正，绝不执行未授权工具。相同写操作去重；重复成功操作不会让深度任务提前结束。
- 持久任务新增阶段检查点。重启只自动重排明确未到工具执行或最终答复阶段的工作；可能已经写入的操作不盲目重放。未完成工具仅在声明可安全恢复的情况下重试。
- 中文词片段与完整编号匹配，相关证据和当前规则分别排序；长期记忆重复写去重、版本与可见范围不降级。历史找回仅限经授权的文件名及本人同范围非敏感用户原话，不把历史当当前业务事实。
- 扩展 schedule_followup 支持 run_agent：经明确交办的目标一次或周期性入队，同槽位幂等，调度与入队原子更新；禁止定时工作递归创建定时任务；角色变化须重新交办。原有零 token 的确定性巡检保持不变。
- 保留现有用量记录。失败调用用量未知时不假报零；预算是每轮执行前按已知用量检查的软边界，不是实际费用上限。

## 配置
BOT_AGENT_ROUNDS（默认48，上限256）
BOT_AGENT_MODEL_CALLS（默认80，上限512）
BOT_AGENT_SECONDS（默认1200，上限7200）
BOT_AGENT_TOKENS（默认250000，0关闭已报告token检查）
BOT_AGENT_RETRIES（默认2，上限5）
这些配置不代表模型能力、账单金额或任务必定完成。运行真实模型前需确认部署端既有模型及成本授权。
